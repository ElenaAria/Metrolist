# Agonis iOS Port — Plan & Status

This document tracks the plan to bring Agonis to iOS with feature parity with
the Android app, using **Kotlin Multiplatform (KMP) + Compose Multiplatform**,
built via **GitHub Actions macOS runners** (no local Mac required).

## Why this approach

- Agonis today is a 100% Android app (Jetpack Compose, Media3/ExoPlayer, Room,
  Hilt, Android widgets, Android Auto, WorkManager-style background services).
  None of that runs on iOS.
- Kotlin Multiplatform lets us reuse the parts of the codebase that are pure
  business logic (networking clients, parsers, matching algorithms) across
  Android and iOS, and Compose Multiplatform lets the UI layer be shared too
  (with platform-specific screens/integrations where needed).
- Apple requires Xcode/macOS to produce a signed `.ipa`, but that machine
  doesn't have to be yours: a GitHub Actions `macos-*` runner does this for
  free (public repos) or with included minutes (private repos), triggered by
  a normal `git push` from Windows. `.github/workflows/ios_build.yml`
  automates this.

## Status: Phase 0 — Foundation (done in this change)

- [x] Added KMP + Compose Multiplatform tooling to the version catalog
      (`gradle/libs.versions.toml`): Kotlin 2.3.21 + Compose Multiplatform
      1.10.3 (verified compatible pairing), Ktor Darwin engine, multiplatform
      lifecycle artifacts.
- [x] Converted `:lrclib` (the LRCLIB lyrics client — pure Kotlin/Ktor, no
      Android APIs) into a real KMP module targeting `android`, `iosX64`,
      `iosArm64`, `iosSimulatorArm64`. This is the first proof that a module
      can be shared as-is. Verified it still compiles for Android
      (`./gradlew :lrclib:compileAndroidMain`) and that `:app` still builds
      unmodified (`./gradlew :app:compileFossDebugKotlin`).
- [x] Added a new `:shared` KMP + Compose Multiplatform module with a minimal
      `App()` composable and `expect/actual` platform detection, to prove the
      shared-UI toolchain compiles for both platforms. Not wired into the
      Android app's UI yet (kept isolated to avoid any risk to the existing
      app while this is unproven).
- [x] Added `iosApp/` — an Xcode project **generated by
      [XcodeGen](https://github.com/yonaskolb/XcodeGen)** from
      `iosApp/project.yml` rather than a hand-authored `.xcodeproj` (far less
      error-prone to author/maintain without access to Xcode). It hosts the
      shared Compose UI via `ComposeUIViewController`.
- [x] Added `.github/workflows/ios_build.yml`: on a `macos-15` runner it
      builds the `:shared`/`:lrclib` Kotlin/Native frameworks, generates the
      Xcode project with XcodeGen, and builds `iosApp` for the iOS Simulator.

### Important: this hasn't been verified on a real Mac/Xcode yet

Kotlin/Native can only *link* Apple binaries on macOS, so none of the iOS
pieces above can be verified from this Windows machine — only the Gradle
*configuration* and the Android-target compilation were verified locally.
**The first real verification happens when `.github/workflows/ios_build.yml`
runs on GitHub Actions.** To trigger it:

```bash
git push                       # workflow runs automatically on push, or:
gh workflow run ios_build.yml  # trigger manually
```

If it fails, copy the failing step's log back into a chat with me and I'll
fix it — this Mac-in-CI feedback loop is how we'll iterate without you ever
needing Xcode locally.

## Phase 1 — MVP (next)

Goal: a real, usable iOS app with core functionality, built on the Phase 0
foundation.

1. **Networking/data layer → shared**: migrate `:innertube`, `:kugou`,
   `:lastfm`, `:betterlyrics`, `:paxsenix` to KMP the same way `:lrclib` was
   done (they're already Ktor-based; mainly needs swapping OkHttp-only engine
   usage for engine-agnostic `HttpClient()` + per-platform engine deps).
2. **Persistence**: migrate Room usage to Room 2.7+'s official KMP support
   (SQLite driver-based) or SQLDelight, so the local library/queue database
   is shared.
3. **DI**: introduce Koin (KMP-compatible) for the shared module; Hilt stays
   Android-only and wires the Android app to the shared Koin graph, or the
   Android app keeps Hilt for Android-only pieces while shared code uses
   Koin.
4. **Player abstraction**: define an `expect`/`actual` `AudioPlayer` in
   `:shared` — Android implementation wraps Media3/ExoPlayer (already used),
   iOS implementation wraps `AVFoundation`/`AVPlayer`.
5. **Core screens in Compose Multiplatform**: Login/token entry, Search,
   Home/Browse, Now Playing, Local Library — shared UI in `:shared`, hosted
   natively via `MainActivity` (Android) and `MainViewController` (iOS,
   already wired).
6. **CI**: extend `ios_build.yml` to install a provisioning
   profile/certificate from secrets and upload builds to TestFlight via
   `fastlane pilot` or `xcrun altool`/`notarytool`, so you can install builds
   on a real iPhone without Xcode.

## Phase 2 — Feature parity, batch 1

- Lyrics providers (`lrclib` ✅, `kugou`, `betterlyrics`, `paxsenix`) — all
  portable once on KMP.
- Downloads/offline caching — iOS equivalent of Media3 `DownloadManager`
  using `FileManager` + a shared metadata layer.
- Last.fm scrobbling — portable (already Ktor-based).
- Theming, dynamic color — Compose Multiplatform supports Material3 on iOS;
  Material You dynamic color has no iOS equivalent, needs a fallback palette.
- Equalizer — platform-specific: Android `AudioEffect`/`Equalizer` API vs
  iOS `AVAudioUnitEQ`, behind a shared interface.

## Phase 3 — Feature parity, batch 2 (advanced/networked features)

- Listen Together (protobuf + WebSocket) — portable via Ktor WebSockets +
  `kotlinx-serialization` protobuf, since it's not Android-specific already.
- Discord Rich Presence (raw gateway WebSocket) — portable the same way.
- NAS cache (WebDAV client) — portable via Ktor.
- Backup/restore — format is already just files; needs iOS file-picker UI.

## Phase 4 — iOS-native integrations (no Android equivalent to port from)

- **Widgets**: WidgetKit target (separate small Swift/SwiftUI code, not
  shared).
- **CarPlay**: parallel to Android Auto, iOS-native `CarPlay` framework.
- **Background audio**: `AVAudioSession` + iOS background modes, replacing
  Android's foreground service pattern.
- **Shazam-style recognition**: iOS can use Apple's real `ShazamKit`
  framework directly (this is actually easier than the Android
  implementation, which reimplements Shazam's fingerprinting algorithm from
  scratch).

## Known follow-ups / cleanup

- `compose.runtime`/`compose.foundation`/etc. accessor properties used in
  `shared/build.gradle.kts` are flagged deprecated by Compose Multiplatform
  1.10.3 in favor of direct module coordinates — functional today, but should
  be migrated to explicit `org.jetbrains.compose.*` coordinates once those
  are confirmed stable, to avoid breakage when the accessors are removed.
- `DEVELOPMENT_TEAM` in `iosApp/project.yml` is empty; needs a real Apple
  Developer Team ID once you have (or don't need, for simulator-only builds)
  an Apple Developer account, to run on physical devices or submit to
  TestFlight/App Store.
- No app icon / launch screen assets yet — cosmetic, low priority until
  Phase 1 UI exists.
